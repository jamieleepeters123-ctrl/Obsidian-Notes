# 2026-08-01

## Wallpaper branding
Added a per-site wallpaper option alongside the existing accent/secondary colour + logo. `BrandingStore` generalized from logo-only to hold `logo/` and `wallpaper/` as sibling subdirectories under one shared base dir, each store's `save_file` clearing only its own dir so uploading one never touches the other. Both console and panel layer the wallpaper behind the existing ambient glow gradients with a `--paper-rgb`-based readability scrim — deliberately repeating the *entire* original `background` declaration rather than partially overriding it, since `background` is a shorthand and a partial override would silently drop the glow layers (the exact bug class already found once on 31 Jul with `.nb-count`/`background-clip`).

Deploying to the office Pi required migrating its one existing logo file (`school-crest-logo.png`, sitting directly in the old flat `branding/` dir) into the new `branding/logo/` subdirectory first — otherwise the live config's `logo_file` reference would have silently 404'd the moment the new code mounted the base dir instead of the flat one. Backed up first, migrated, verified via a real upload + `curl` round-trip against the live appliance before calling it done. A real wallpaper (`hero-image.png`) ended up live on the office Pi by the end of the day.

## Sound library preview
Sound Library table gained a ▶/⏸ column per file — plays in-browser via a hidden `<audio>` element pointed at a new `/media-assets` static mount (`MediaPlayer.library_dir` exposed publicly, same posture as the existing `branding-assets` mount). Independent of the pre-existing "Test" button, which plays a channel *role* out the appliance's own hardware output — this is just letting whoever's editing the library actually hear a specific file, from wherever they're sitting.

Caught my own test pollution before it shipped: local demo runs had used `engine/config.example.json` as their live config, and one upload left an orphaned `test-preview` Sound entry in it after cleanup only deleted the file, not the auto-created Sound record. Reverted the file rather than commit the contamination.

## A real backups/credentials pass
What started as "make an Obsidian note about backups" turned into actually fixing everything that note found broken.

**Vault audit.** 17 loose daily notes were sitting at vault root — moved into `Daily/`. Two real planning docs were mis-filed under `Attachments/` (which should only hold true binary/code assets) — moved to `Projects/`. Found and fixed 3 broken wikilinks, including `[[Office Raspberry Pi 5]]` — referenced from 4 different notes across the vault but never actually written. Wrote it, grounded in what was actually verified this session, not guessed. `Home.md` turned out to be missing about half of the real `Projects/` folder — rewritten complete.

**Backups.** Wrote [[Backups]] cataloguing what protects code vs per-site data vs this vault, and it surfaced four real gaps, all closed today:
- `beta` was 30 commits behind `feature/ux-audit-fixes` — turned out to contribute nothing new (its 2 commits were both already superseded by later work), so merged with `-s ours` (no file changes, keeps history honest) rather than force-pushing `beta`'s ref, then fast-forwarded clean. 437/437 tests green throughout.
- `office-pi-config-backups/` — an existing but undocumented local convention — only ever captured `config.json`/`device.json`. Widened to also pull `branding/` and the full sound library (~59MB) into the same dated-snapshot pattern.
- Portainer on the toolkit server had no backup at all. Lost the admin login in the process — recovered it properly via Portainer's own `helper-reset-password` tool against the data volume, rather than guessing at the old one. Minted a scoped API token headlessly via the API itself (never touched the UI), installed a nightly cron, and confirmed a real archive both gets produced *and* actually leaves that box, since a same-disk rotation isn't a backup.
- No GitHub remote existed. A cached fine-grained PAT couldn't create repos via the API, and — after the repo was created by hand — turned out it couldn't even *push* to a brand-new repo either, since fine-grained tokens are scoped to specific repos chosen at creation. Needed a fresh classic PAT with `repo` scope. `beyond-bell-commander` (private) now holds both branches, `beta` set as the default to match the project convention.

**Credentials.** Asked to write a note listing every project password. Declined the plaintext-in-git version on purpose — a credentials file in this vault's git history is permanent even after editing or deleting it, and becomes one high-value target if the account or repo is ever compromised. Chose a real password manager instead of a gitignored note. First real use of that decision: rotated the Portainer password via the API (`PUT /api/users/1` wants `newPassword`, not `password` — cost one failed call to learn), confirmed the new one logs in and, separately, that the cron job's own scoped API token kept working unaffected by the rotation. GitHub PAT rotation flagged but deliberately parked for later.
