# 2026-08-01

## Wallpaper branding
Added a per-site wallpaper option alongside the existing accent/secondary colour + logo. `BrandingStore` generalized from logo-only to hold `logo/` and `wallpaper/` as sibling subdirectories under one shared base dir, each store's `save_file` clearing only its own dir so uploading one never touches the other. Both console and panel layer the wallpaper behind the existing ambient glow gradients with a `--paper-rgb`-based readability scrim — deliberately repeating the *entire* original `background` declaration rather than partially overriding it, since `background` is a shorthand and a partial override would silently drop the glow layers (the exact bug class already found once on 31 Jul with `.nb-count`/`background-clip`).

Deploying to the office Pi required migrating its one existing logo file (`school-crest-logo.png`, sitting directly in the old flat `branding/` dir) into the new `branding/logo/` subdirectory first — otherwise the live config's `logo_file` reference would have silently 404'd the moment the new code mounted the base dir instead of the flat one. Backed up first, migrated, verified via a real upload + `curl` round-trip against the live appliance before calling it done. A real wallpaper (`hero-image.png`) ended up live on the office Pi by the end of the day.

## Sound library preview

Independent of the pre-existing "Test" button, which plays a channel *role* out the appliance's own hardware output — this is just letting whoever's editing the library actually hear a specific file, from wherever they're sitting.

- `beta` was 30 commits behind `feature/ux-audit-fixes` — turned out to contribute nothing new (its 2 commits were both already superseded by later work), so merged with `-s ours` (no file changes, keeps history honest) rather than force-pushing `beta`'s ref, then fast-forwarded clean. 437/437 tests green throughout.

## Zones/Setup reorganization + quick daily bell-sound upload
Original complaint: the top-level **Zones** tab (live mute/level/pink-noise) and Setup's **Sounds & Zones** sub-tab (zone/bell/group configuration) read as the same thing under similar names. First attempt was a full VZX-8-style sidebar reskin, built out fully and rejected outright ("i dont like it" / "wrong approach altogether, let's rethink it") — cleanly reverted, nothing had been committed. Redone the way asked: one change at a time, verified end-to-end after each. Speaker zones + Bell groups moved into the Zone menu; Sounds folded into Media Player; a stray AHM-only-assumption bug caught along the way (`isAtlas ? X : isXilica ? Y : /* assumed AHM */ Z` patterns silently treated the local demo driver as AHM in several labels/buttons — fixed with explicit `isAHM` checks and genuine neutral fallbacks, e.g. "Channel" instead of assumed "AHM ch").

Added a Today-page quick action: upload an audio track and use it as the daily bell sound — on request, made a *permanent* change to the default template's main bell sound, not a today-only override. Given its own window (moved out of the Next Bell card, after Today's bells per a follow-up instruction), with a large music icon, adjustable max length, and a 1s fade in/out. Converts server-side via ffmpeg.

**Real bug, real file**: `(Sting) Happy.mp3`, an actual file from the user's own library, got rejected by upload — `SAFE_NAME`'s regex required an alphanumeric first character, silently contradicting its own error message which explicitly listed `(` as allowed. Fixed the regex.

**"Ring bell not playing full track"** — traced through the real call chain (`manual_ring` → `driver.trigger_bell` → for Xilica, `self.media.play()`) rather than guessed at. Two plausible hypotheses ruled out by direct testing: the "now playing" 6s-default timer (confirmed cosmetic-only, no real stop call) and MP3 decoding in general (a synthetic sine-wave MP3 decoded exactly). Redirected by explicit instruction — "use a format that best suited for the application" — to reconsider the conversion target itself: switched from MP3 to uncompressed WAV (real MP3s hit LAME encoder-delay/VBR frame-boundary decode ambiguity a clean synthetic test wouldn't surface). Verified via the actual playback code path (`soundfile.read()`) both locally and on the office Pi — exact duration preserved across several real test files.

Sound Library gained a Length column (probed via `soundfile.info()`, a header-only read); the Today page's "now playing" countdown was still using a hardcoded 6.0s default whenever a Sound's `duration_s` wasn't explicitly set (true for every quick-uploaded sound) — fixed to fall back to the same real-file probe, so the countdown now matches actual playback length instead of a guess.

Also fixed, same session: the System page's "Sound system connection" card always read "AHM address" regardless of the site's real driver — same assumed-AHM bug class as above, now keyed off `drv.running` (the real lowercase driver kind) instead of a hardcoded label.
